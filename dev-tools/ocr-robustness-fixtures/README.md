# OCR Robustness Fixtures

Dev-only tool. Takes clean receipt files and generates randomized,
camera-photo-like variants (perspective skew, paper waviness, uneven
lighting, lens blur, sensor noise, desk background) so you can test how
robust this repo's receipt parsing (e.g. `zomatoParser.js`) is to the kind
of image quality a phone camera actually produces, instead of only ever
testing against pristine PDFs/screenshots.

**This is a dev-only tool, never imported by `server.js` or run in
production.** Its dependencies (`sharp`, `pdf2pic`) live in the repo root's
`package.json` under `devDependencies`, so `npm ci --omit=dev` (or any
production install) skips them. Every generated file's EXIF
`ImageDescription` is stamped
`SYNTHETIC TEST FIXTURE - generated by ocr-robustness-fixtures, not a real
receipt` so a generated fixture can't be mistaken for a real capture later.

It deliberately does **not** simulate occlusions (fingers/thumbs on the
paper) or hand-shaped shadows — those don't affect OCR robustness, they
only help an image pass as "someone's hand really held this," which isn't
this tool's purpose.

## Setup

Install dependencies once from the **repo root** (this tool shares the
root `node_modules`, not its own):

```bash
npm install
```

PDF input also requires **GraphicsMagick** and **Ghostscript** on your
`PATH` (used by `pdf2pic` to rasterize pages). On Windows:

```powershell
choco install graphicsmagick ghostscript
```

If you only ever feed in `.png`/`.jpg`/`.jpeg` files, you can skip this.

## Usage

1. Drop clean receipt files (`.pdf`, `.png`, `.jpg`, `.jpeg`) into
   `dev-tools/ocr-robustness-fixtures/input/`.
2. From the repo root, run:

   ```bash
   npm run ocr:fixtures
   ```

3. Degraded `.jpg` fixtures land in `output/`, one per input image (PDFs
   produce one file per page, suffixed `-p1`, `-p2`, ...).

Each run re-randomizes which effects fire and how strongly, per `config.js`
— run it multiple times (or point it at the same input repeatedly) to build
a varied test set.

## Tuning

Edit [`config.js`](./config.js): every effect has a `probability` (chance
it's applied to a given image) plus a strength/range knob. Turn an effect
off entirely by setting its `probability` to `0`, or crank up
`sensorNoise`/`lensBlur` to stress-test OCR error tolerance specifically.

## Pipeline

```
src/
├── index.js              CLI entry: walks input/, dispatches per file
├── pdfRender.js           PDF pages -> PNG buffers (pdf2pic)
├── pipeline.js            per-image effect chain + JPEG encode
├── effects/
│   ├── homography.js      perspective-warp math (no native deps)
│   ├── perspective.js     corner-jitter + rotation, via homography
│   ├── waveDistort.js     sine-wave paper bending
│   ├── background.js      procedural desk/table backdrop
│   ├── lighting.js        vignette, flash bloom, uneven ambient light
│   ├── noise.js           gaussian sensor grain
│   └── blur.js            gaussian lens defocus
└── utils/
    ├── random.js
    └── raw.js             sharp <-> raw RGBA buffer helpers
```
